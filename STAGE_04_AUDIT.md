## 2. Общество: что уже есть

- **Сословия** (`universes/*.world.ts`): id, `standing` 0–5, `income`, занятия. Смена: `fx.socialClass`, `fx.classStep` (`effects.ts:237`, берёт первое сословие со ступенью ±1 — при равных ступенях выбор неоднозначен), милость двора в Лиревале, наследование.
- **Репутация и карма:** ±100. **Фракции:** `character.factions`, ±100, по три на мир. **Слава рода:** `lineage.renown`, ±100.
- **Шкалы миров:** скверна и угли, милость Системы, искажение ци, сердце Дао и кармический долг, угроза Врат и известность, милость двора и скандал.
- **Условия:** `socialClass`, `standing`, `reputation`, `faction`, `renown`, `karma`, `meter`.

**Нет:** правил общественного подъёма и падения для персонажа (только отдельные события), влияния на сословие от достатка, конфликтов между фракциями, отношений между семьями как данных. В `LifeView` золото, сословие и фракции передаются как сырые значения: нет названий фракций, описания сословия и прогноза дохода.

## 3. События

`EventDefinition`: условия, вес, `cooldown`, `maxOccurrences`, `lineageMax`, виды `life … legacy`. Вес делится на `1 + повторы`, последние 4 события исключаются. Новый эффект или условие затрагивает объединение типов, `applyEffect`, `checkCondition`, `describeCondition`. Существующий движок подходит, новый не нужен.

## 4. Server authority: риски текущего режима

| Риск | Где | Последствие |
| --- | --- | --- |
| Режим выбирается одной проверкой `/api/health` за загрузку страницы и не меняется | `lib/store/index.ts` | Кратковременный сбой — все новые жизни этой вкладки тихо становятся локальными |
| Значок режима скрыт на телефоне | `store-badge.tsx:13` (`hidden … sm:inline-flex`) | Игрок на телефоне не узнает о локальном режиме |
| Индекс localStorage: прочитать-изменить-записать | `store/local.ts:58` | Две вкладки теряют id друг друга, жизнь не видна в списке |
| Наследование пишет два ключа подряд | `store/local.ts:199` | Сбой между записями оставляет лишнюю запись |
| `seed`, `rngState`, золото и результаты лежат в браузере, соль наследника — клиентская | `store/local.ts` | Всё можно подделать; `parseSave` проверяет форму, а не происхождение |
| `actionId` в локальном режиме игнорируется | `store/local.ts:129` | Журнала повторов нет |
| Нет импорта и экспорта; ни один endpoint не принимает состояние | API | Перенести жизнь на сервер сейчас невозможно |
| Лимит тела запроса 16 КБ | `bootstrap.ts:20` | Полная жизнь не поместится: импорту нужен свой лимит только на своём маршруте |
| Нет тестов локального режима | e2e, API | Перенос придётся покрывать с нуля |

Облачный режим уже безопасен: схемы `z.strictObject`, транзакция с блокировкой, `actionId`, `expectedVersion`. Жизнь с серверным id никогда не падает в локальный режим.

## 5. Сохранения и миграции

`SAVE_SCHEMA_VERSION = 3`. Новые поля состояния требуют шага в `MIGRATIONS` и проверки в `parseSave`. Шаг детерминирован, не трогает `rngState` и ничего не удаляет. В рабочей среде сейчас Stage 02 (формат 2): при выкладке сохранения пройдут цепочку 2 → 3 → 4.

## 6. Вывод

Stage 04 расширяет существующие модули: `life/income.ts`, годовой цикл, конфигурацию миров, DSL событий, досье. Отдельные движки на каждый мир не нужны. Первый приоритет — безопасный перенос локальных жизней, потому что любая новая экономика в браузере подделывается так же легко, как и старая.
