# Stage 13 — план

Одна правка, которая следует из плана запроса.

## Индексы поиска

Два индекса по выражению, без смены колонок и данных:

- `lower(id_display_name)` где имя не пустое
- `lower(id_username)` где имя не пустое

Prisma не описывает функциональный индекс в схеме. SQL миграции — источник. В `schema.prisma` только комментарий, чтобы `migrate diff` не предлагал их удалить нельзя: Prisma их не видит. Поэтому миграция ручная, `db:migrate` её применит, схему клиента не меняет.

Поиск в коде не меняется: `equals` + `mode: insensitive` уже даёт `lower(column) = lower($1)`.
