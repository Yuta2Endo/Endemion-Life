# Endemion Life — Stage 05: план

Основание: [STAGE_05_AUDIT.md](STAGE_05_AUDIT.md). Один вертикальный срез: ядро, контент шести миров, интерфейс, тесты, документы. Значения наград — стартовые.

## 1. Состояние (`state.adventure`)

```
adventure: {
  discovered: string[]            // открытые места, по id
  active: { id, step, since } | null
  done: string[]                  // завершённые приключения
  failed: string[]                // проваленные
  log: { adventureId, age, kind }[]  // не больше 24 записей
}
```

Формат сохранения 6. `migrateV5` добавляет пустое приключение и ничего не удаляет. `parseSave` принимает только известные id мест и приключений мира этой жизни.

Наследник приключения не получает: `succeed` ставит пустое. Открытые места — личный опыт, не имущество.

## 2. Контент (`adventure/content.ts`)

Описание, не код правил:

- **Место**: id, название, текст, `minAge`.
- **Приключение**: id, название, место, `minAge`, `requires` (другие приключения), шаги.
- **Шаг**: текст, варианты. Вариант — `id`, текст, `requires` (условия Narrative Engine), `check` (`StatCheck` или нет), успех и провал.
- Исход: текст, эффекты (те же `Effect`, что у событий), переход `next` (следующий шаг), `complete` или `fail`.

По одному приключению на мир, 2–3 места, 3 шага. Приключения ссылаются только на навыки, способности, фракции и условия своего мира.

## 3. Движок (`adventure/adventure.ts`)

Чистые функции, как остальной game-core.

- `presentAdventure(state)` — что видит игрок: открытые места, доступные приключения (возраст, место открыто, предпосылки, не сделано и не провалено), текущий шаг с вариантами, награды вариантов текстом, причина закрытия.
- `discover(state)` — в год жизни, из отдельного потока `seed::adventure::rngState`. Открывает не больше одного места за год, только если возраст подошёл и место ещё не открыто. Основной генератор не читает.
- `begin(state, id)` — проверки: жизнь жива, нет `pending`, возраст, место, предпосылки, приключение не в `done` и не в `failed`, другого активного нет. Ошибка — `GameRuleError` (`ADVENTURE_LOCKED`).
- `venture(state, choiceId)` — только по текущему шагу. Вариант существует и `requires` выполнены. Проверка, если есть, бросается из потока приключения, не из основного генератора. Шаг отмечается до эффектов. Эффекты — `applyEffects`. Переход, завершение или провал пишутся в состояние и в журнал. Повторно награду не даёт: закрытый шаг не переигрывается, а `actionId` на сервере возвращает прежний ответ.
- `abandon(state)` — сдаться. Активное уходит в `failed`, награды нет. Сдаться можно один раз.

Награды шагов — опыт, золото, навык, репутация, отношение фракции, способность. Способность из списка мира, которой у персонажа ещё нет; повторное получение той же способности эффектом и так ничего не делает.

## 4. Действие

`GameAction` дополняется `{ type: "venture"; adventureId?: string; choiceId?: string }`:

- только `adventureId` — начать;
- только `choiceId` — шаг активного;
- оба пустые — сдаться.

`applyAction` пишет запись истории `adventure`. Схема `gameActionSchema` — `z.strictObject`, id по `optionId`.

Пока `pending` не пуст, любое `venture` отклоняется: сначала ответ на событие года.

## 5. Интерфейс

Новая вкладка досье «Путь» (`dossier.tsx`), на существующих `Panel` и `Button`:

- места мира: открытые и ещё не открытые (без названия — «неизведанное место»);
- приключения: доступные с кнопкой «Отправиться», закрытые с причиной (возраст, место, другое приключение);
- текущее: текст шага, варианты, у варианта с проверкой — шанс, у всех — награда текстом;
- сдача;
- завершение: исход последнего шага и что получено (это же есть в истории).

RU/EN в `messages.ts`. Кнопки с `aria-label`, `data-testid`.
