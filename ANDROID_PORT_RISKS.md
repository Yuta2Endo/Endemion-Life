# Endemion Life — Android port risk register

Date: 2026-11-06. Source commit `2812b01`. Severity is impact if the risk hits during the port. Probability is for this architecture (remote Capacitor WebView), not for a rewrite.

| ID | Description | Severity | Probability | Impact | Mitigation | Systems |
| --- | --- | --- | --- | --- | --- | --- |
| R1 | Bundled or `capacitor://` origin cannot send `el_session` and fails CSRF because `Origin` is not in `CORS_ORIGINS`. | CRITICAL | High if someone bundles the site; low if the shell stays on the live URL | Every signed-in action returns 401/403. A "fix" that opens CORS or clears `COOKIE_SECURE` weakens production. | Keep the WebView on `https://life.endemion.online`. Do not add a second origin. | Auth, saves, Nginx, `RequestGuard` |
| R2 | Endemion ID opened in Chrome Custom Tabs sets the cookie in Chrome, not in the WebView. The app looks logged out. | HIGH | High if Custom Tabs are used; low if the redirect stays in the WebView | Users cannot reach existing lives. | Finish OIDC inside the same WebView. If the IdP blocks that user agent, switch to a TWA instead of copying tokens into the app. | Endemion ID, session cookie |
| R3 | Google Play rejects a thin WebView wrapper. | HIGH | Medium | Store listing blocked after the shell is built. | Decide before public release. Fallback is a Trusted Web Activity on the same URL, not a native rewrite. | Release, shell |
| R4 | This PC has JDK 8 only, no Android SDK, and `corepack` is not on `PATH`. | HIGH | Certain until installed | Stage 03 cannot compile. A hand-written `android/` tree would be a fake project. | Install JDK 21, SDK, and pnpm 12 before Stage 03. Record the versions that actually built. | Build |
| R5 | WebView cookie wiped by the OS, or a new application id, makes the phone look empty. Lives are still on the server. | HIGH | Medium | Support reports of "lost progress". | Login with the same Endemion ID. Freeze the package name before the first Play upload. Do not invent a local backup of cloud state. | Accounts, Play signing |
| R6 | Guest play in the WebView, then login to an older account, transfers guest lives once (existing server rule). | HIGH | Medium in testing; low in production if login is required up front | Tester thinks lives jumped accounts. | Stage 05 uses a clean profile and an owner test account. Do not reimplement transfer in the client. | `AuthService` guest transfer |
| R7 | Remote shell shows a blank page when the site or DNS is down. There is no service worker. | MEDIUM | Medium | App feels broken offline. Cloud turns cannot be applied offline anyway. | Native timeout and retry screen in Stage 04. Do not ship the localStorage rules engine as the offline mode. | WebView, local store |
| R8 | `auth.endemion.online` or Google blocks embedded WebView login (user-agent / `X-Frame` / IdP policy). | MEDIUM | Medium | Login dead while the site works in Chrome. | Stop and use TWA, or an owner-approved IdP change. Do not disable TLS or scrape the code. | OIDC |
| R9 | `allowNavigation` too wide, or every link kept in the WebView. | MEDIUM | Medium | Phishing page inside the app, or the game is replaced by `endemion.online`. | Allow only the game host and the IdP host. Send other URLs to the system browser. | Shell, footer links |
| R10 | JavaScript bridge or a debug build ships `ENDEMION_ID_CLIENT_SECRET` / token key. | MEDIUM | Low if the shell stays thin | Account takeover of the OIDC client. | Secrets stay in server env only. Release build is not debuggable. No bridge API for cookies. | OIDC, Capacitor |
| R11 | Trust-all `network_security_config` or ignored SSL errors used to debug a proxy. | CRITICAL | Low if Stage 04 forbids it | Session cookie exposed on a hostile network. | System trust anchors only. Reject the debug workaround in review. | WebView TLS |
| R12 | Bottom tab bar sits under the gesture bar; 11px labels are hard to tap. | MEDIUM | High on current CSS | Mis-taps on year, choices, and tabs. | Stage 02 safe-area and 44px targets. Re-test on a physical phone. | `play-screen.tsx`, `globals.css` |
| R13 | Tablet width ≥ 1024px uses the desktop three-column play screen. | LOW | Medium | Cramped sheet/dossier in landscape. | Stage 02 check just below and above the `lg` breakpoint. | Play layout |
| R14 | Stale `expectedVersion` from two devices. | LOW | High once two devices share an account | One device shows `409 VERSION_CONFLICT` and must reload. This is the designed behavior. | Keep the existing reload copy. Do not merge states on the phone. | Actions, snapshots |
| R15 | Retry after a dropped response double-applies a year. | HIGH | Low; the site already reuses `actionId` | Duplicate age and history. | Stage 05 kills the network mid-action and retries. Do not generate a new `actionId` for a retry. | `play-screen.tsx`, `game_actions` |
| R16 | Local mode starts because `/api/health` failed once, and the player then believes that life is the cloud life. | MEDIUM | Low for a remote shell (the document never loads); medium if a bundled client is built later | Divergent untrusted save. If a bundled client is ever approved, do not create a life when health failed twice without a visible warning. | `store/index.ts`, import |
| R17 | Play App Links on `/api/auth/oidc/callback` claimed by a second app. | LOW | Low | Login code delivered to the wrong app. | Do not add App Links until `assetlinks.json` is correct. The HTTPS redirect works without them. | OIDC callback |
| R18 | Website deploy breaks the shell, or a shell update is required for a game fix. | LOW | Medium for site bugs; low for shell if UI stays remote | Players stuck until the site rolls back. | Game fixes ship with the website (`docs/ROLLBACK.md`). The shell only changes for native bugs. | Deploy, shell |
| R19 | Shared 2 GB server and shared S3 key (Stage 01.5, not rechecked 2026-11-06). | MEDIUM | Already true for the website | Outage or backup-scope issue hits Android too. | Owner actions already listed in `STAGE_01_5_FINAL_REPORT.md`. Not an Android code change. | Production host |
