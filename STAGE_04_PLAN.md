# Endemion Life — Stage 04: план

Основание: [STAGE_04_AUDIT.md](STAGE_04_AUDIT.md). Работа идёт законченными вертикальными срезами: код, тесты и документы каждого среза готовы до начала следующего. Интерфейс появляется только для работающих механик. Значения ниже — стартовые; они уточняются прогонами баланса, а итоговые записываются в отчёт.

## Срез 1. Server authority: перенос локальных жизней

**Импорт.** `POST /api/lives/import`, тело `{ importId, state, history }`, схема `z.strictObject`, свой лимит размера только на этом маршруте (глобальные 16 КБ не меняются).

Сервер не доверяет присланному:
1. `parseSave` (включая перевод старых форматов) и `kinProblem`.
2. Новые серверные `seed` и `rngState`: будущие броски нельзя предсказать.
3. Нераскрытые `potential`, `destiny` и спящие таланты бросаются заново.
4. Проверка правдоподобия в `game-core` (`sanitizeImport`): золото ограничено пределом по возрасту и миру, срабатывания ограничены; всё, что исправлено, перечисляется в ответе и показывается игроку.
5. Отметка `continuedBy` запрещает импорт уже продолженной жизни.

**Идемпотентность.** Уникальный ключ `(player_id, import_id)`: повтор возвращает ту же жизнь, а не создаёт вторую. Лимит живых жизней действует как обычно.

**Схема (только добавление).** `lives.origin` (`server` по умолчанию, `local-import`), `lives.import_id UUID NULL`, уникальный индекс. Импортированная жизнь помечена навсегда: это пригодится для будущих общих рейтингов.

**Клиент.**
- Локальный режим не удаляется.
- После подтверждённого импорта локальная запись помечается перенесённой, но не стирается, пока игрок сам её не удалит.
- Ошибка связи оставляет локальную запись нетронутой, повтор идёт с тем же `importId`.
- `detectStoreKind` перепроверяет связь перед созданием жизни и не запоминает неудачу навсегда.
- Заметное предупреждение о локальном режиме на всех экранах, включая телефон; метка «в браузере» в списке жизней; кнопка «Перенести на сервер».

**Тесты.** API: успех, повтор, чужой игрок, лишние поля, повреждённое сохранение, завышенное золото, старые форматы, размер, одновременные запросы, новый seed. E2E: локальная жизнь при отключённом API, перенос, продолжение на сервере, обновление страницы, телефон.

## Срез 2. Economy Engine (формат сохранения 4)

Новый модуль `economy/` и поле `state.economy`:

| Правило | Начальное значение |
| --- | --- |
| Предел золота | `MAX_WEALTH` = 1 000 000 000 в едином эффекте и наследстве |
| Расходы на жизнь | С 16 лет, по ступени сословия: 0, 1, 2, 4, 6, 10; конфигурация мира может менять их |
| Налог | Доля дохода по миру, округление вниз, только с положительного дохода |
| Цикл мира | Спад, обычный год, подъём: множитель дохода 0.8 / 1 / 1.2, отдельный поток генератора |
| Нехватка денег | Золото не уходит ниже 0, растёт счётчик `hardship`; долг как отрицательное значение не вводится |
| Журнал | Доходы и расходы последнего года и короткая история (не больше 10 лет) для интерфейса |

**Детерминированность.** Цикл бросается из потока `seed::economy::год`, основной поток новых чисел не читает. Гарантия та же, что в `STAGE_03_1_AUDIT.md`.

**Совместимость.** `migrateV3` только добавляет `economy` с нейтральными значениями, `rngState` не трогает. Тесты на сохранениях форматов 1, 2 и 3 (фикстура формата 3 записывается кодом до изменений).

**Баланс.** Прогон полных жизней во всех мирах: у типичного взрослого с ремеслом доход выше расходов, у бедных сословий расходы не больше дохода сословия, золото не переполняется за тысячелетнюю жизнь культиватора.

**Интерфейс.** Раздел досье «Хозяйство»: золото, доходы и расходы по статьям, состояние экономики мира, нехватка; пустое состояние для детей; RU/EN, телефон, клавиатура.

## Срез 3. Society и особенности миров

Общие правила с конфигурацией мира (`world/economy.ts` или расширение `*.world.ts`), а не шесть движков:

| Мир | Экономика | Общество |
| --- | --- | --- |
| Пепельные Королевства | Десятина Ордена как налог | Привилегии знати, влияние Ордена |
| Арденвейл | Пошлина гильдии, подъём торговли | Вес гильдий и лиги купцов |
| Девять Рек | Доля клана, общинная поддержка в нужде | Статус в клане и союзах |
| Небесный Предел | Доля секты, духовные ресурсы | Иерархия секты |
| Нео-Сеул | Городской налог, высокая стоимость жизни | Гражданские права, корпорации |
| Империя Лиреваль | Сборы короны | Милость двора, майорат |

**Механики.** Вычисляемое положение в обществе из сословия, репутации, достатка и фракций; мобильность с паузой между сменами и точным выбором сословия при равных ступенях; конфликт фракций мира как шкала с годовым законом.

**События** (условия, вес, cooldown, ограничение повторов, общий Narrative Engine): финансовый кризис, подъём и падение сословия, конфликт гильдий, борьба за влияние, экономическая возможность, семейный спор о ресурсах, политические последствия, восстановление. Общая часть и не меньше одного своего события на мир. Новые условия: `wealthAtMost`, `hardship`, `cycle`.

**Интерфейс.** Раздел «Положение в обществе»: сословие, фракции с названиями, влияние.

## Срез 4. Рынок (только если срезы 1–3 устойчивы)

Небольшое серверное действие покупки и продажи товаров мира. Цена покупки всегда выше цены продажи при любом состоянии цикла (тест на отсутствие бесконечного источника золота). Если срез не войдёт в этап, интерфейса рынка не будет, а отчёт скажет об этом прямо.

## Проверки каждого среза

`pnpm check`, `pnpm test:api`, `prisma migrate diff --exit-code`; `pnpm test:e2e` на компьютере и Pixel 7 после срезов с интерфейсом. Падения разбираются и исправляются, тесты не отключаются и не ослабляются.
