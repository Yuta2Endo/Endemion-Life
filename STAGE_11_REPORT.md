## 2. Что сделано

| Требование | Как |
| --- | --- |
| Проверка описаний | `contentProblems()`. Пустой список — всё сходится |
| Битый шаг | `next` на шаг, которого нет, или на себя |
| Повтор | Одинаковые id места, приключения, шага или варианта |
| Чужая награда | Способность, навык, фракция, шкала, сословие, ремесло или образование не из этого мира |
| Вторая дорога | По одной на мир, `requires` — первая, место уже существующее |
| Повтор игры | Пройденное лежит в `done`. Второй старт закрыт |
| Фарм | Наград сверх первой дороги нет. Край двигается один раз и слабее |

## 4. Решения

- Новый формат контента не заводился. Проверка читает те же объекты, из которых игра берёт шаги.
- Свой список можно передать в `contentProblems`, чтобы проверить сломанную копию, не трогая живой контент.
- Вторая дорога не получает своей строки в `ADVENTURE_MARK`. След на край слабее и общий: напряжение −3, благополучие +3. Провал — как раньше, вдвое слабее и в другую сторону.
- Хроника рода не менялась: дело пишется для любого приключения мира.
- Цель освоения `deed` по-прежнему закрывается первой дорогой. Вторая — для тех, кто первую уже прошёл.

## 8. Дополнено в тот же день

- `eventProblems()` проверяет события года тем же способом: повтор id, пустой список вариантов, продолжение `schedule` в никуда, последствие `later` без описания, награда не из этого мира. На живом контенте список пуст.
- Цель `deed` зачитывается, только когда пройдены все приключения мира. Одной дороги больше не хватает. Редкая цель «Хозяин мира» от этого тоже зависит.

## 10. Известные проблемы

- Вторая дорога двигает край одинаково во всех мирах. У первой след свой.
- Если у второй дороги уберут `requires`, она начнёт двигать край как первая. Сейчас `requires` есть у всех шести, и проверка это не требует.
- Проверка событий не смотрит флаги и темперамент: у них нет общего списка.
