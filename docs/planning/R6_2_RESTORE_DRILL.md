# R6.2 — Учебное восстановление из резервной копии

**Статус:** реализовано и проверено локально; релиз ожидает деплоя  
**Save schema:** 14 (без изменений)  
**DB migration:** нет  
**Затронуты:** `infrastructure/scripts`, документация; runtime-код игры не менялся

## 1. Гипотеза и срез

Если восстановление из резервной копии можно повторить одной командой и получить проверяемый отчёт, то backup перестаёт быть обещанием и становится проверенной процедурой.

R6.2 закрывает первую часть волны R6 — **restore drill**. Android AAB, staging/canary и push/deep links в этот срез не входят.

## 2. Что добавлено

- `infrastructure/scripts/backup-drill.sh` — обёртка над существующим `verify-backup.sh`:
  - запускается из корня проекта на сервере;
  - использует работающий контейнер `backup`;
  - берёт блокировку, чтобы не пересечься с очередной копией;
  - выбирает самый новый dump из `daily/` или `manual/`;
  - отказывается запускаться, если копия старше 26 часов (порог меняется `--max-age-hours`);
  - делает полное пробное восстановление во временную базу;
  - проверяет применённые миграции Prisma и базовые таблицы;
  - пишет JSON-отчёт в `BACKUP_HOST_DIR/drills/restore-drill-<UTC>.json`;
  - не изменяет рабочую базу.
- Раздел «Учебное восстановление» в `docs/DATABASE_BACKUPS.md`.

## 4. Безопасность

- Живая база не переименовывается и не останавливается.
- Восстановление идёт в отдельную scratch-базу, которая удаляется в `trap` при любом исходе.
- Скрипт не принимает путь к произвольной базе и не делает cutover.
- Пароли БД не выводятся: используются переменные окружения контейнера.
- Отчёт содержит только имя файла копии, возраст и статус.

## 5. Ограничения

- Это проверка восстановления, а не полная репетиция переключения production на восстановленную базу.
- После restore не запускается прикладной smoke (API + запись + чтение). Это отдельный шаг.
- Нет автоматического расписания drill: запуск ручной.
- Нет проверки восстановления из внешнего S3: проверяется локальная копия.
- Android AAB, staging/canary, push/deep links и store-метаданные остаются на следующие срезы R6.

## 6. Откат

Миграций нет. Откат — вернуть предыдущий commit; скрипт и документация не влияют на runtime.
