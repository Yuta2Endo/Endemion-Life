# Stage 04 — Living Worlds: план реализации

**Статус:** backend, web-витрина и документация реализованы, проверены и развёрнуты; production работает на `cf7d098`.

## Цель

Добавить серверный общий мир (shared world) для каждой из шести вселенных:

- одинаковое для всех читателей состояние;
- детерминированный сезонный `tick` от seed и журнала команд;
- исторические снимки сезонов;
- правки администратора с аудитом;
- воспроизведение журнала и проверка контрольной суммы;
- публичную сверку с мирами отдельных жизней без персональных данных.

Stages не меняет формат сохранения жизни: `SAVE_SCHEMA_VERSION` остаётся **14**. Общий мир —
отдельная проекция, а не часть `GameState`.

## Фазы

1. **Чистый движок.** Типы `SharedWorldState`, команды, `tick`, replay, каноническая
   контрольная сумма, проверка формы, сверка с `WorldState` жизни.
2. **Схема и миграция.** `World`, `WorldSeason`, `Settlement`, `Faction`, `WorldEvent`,
   `WorldCommand`, `WorldAudit`; уникальные ключи; аддитивная миграция.
3. **API.** Публичное чтение, ops-tick, ops-команды, replay, metrics, reconciliation.
   Ленивое идемпотентное создание шести миров.
4. **Тесты.** Детерминизм, replay, ограничения, шесть вселенных, конкурентные tick,
   откат транзакции, аудит, независимость одиночной жизни, отсутствие PII.
5. **Документация.** Модель, tick, маршруты, результаты тестов, риски.
6. **Веб-интерфейс (после API).** Панель «Живые миры» на `/worlds`: шесть вселенных,
   выбор мира в той же странице, сезон, поселения, товары, фракции и последние вести.
   Подробности — в `WEB_UI.md`.

## Ключевые решения

- **Seed из id вселенной**, а не случайный: `shared:<universeId>:v1`. Все читатели получают
  один и тот же мир без координации.
- **Сезон — целое число**, старт с 1. `tick` увеличивает ровно на 1.
- **Rng stream** — `shared:<новый сезон>`; состояние RNG не хранится, поэтому replay
  воспроизводит любой сезон с начала.
- **Источник истины** — `worlds.state` (`SharedWorldState`). Нормализованные таблицы —
  проекции для чтения и отчётов; их можно перестроить из состояния.
- **Журнал команд** — единственный вход replay: `tick` и правки администратора.
  Начальное состояние всегда `newSharedWorld(universeId, seed)`.
- **Один advisory lock на вселенную** сериализует tick и команды; вся запись идёт
  в одной транзакции.
- **Операторский доступ** — отдельный `WORLD_OPS_TOKEN` из `process.env` и заголовок
  `x-world-ops`. `config.ts` не менялся. Нет токена, он короче 16 символов или не совпал —
  404.
- **Одиночная жизнь независима.** Действия жизни не читают и не пишут таблицы общего мира.

## Критерии приёмки

- [x] Шесть миров создаются лениво и идемпотентно.
- [x] Два независимых гостя видят одинаковое состояние.
- [x] Tick меняет сезон ровно на один и воспроизводится из seed.
- [x] Replay совпадает с сохранённой контрольной суммой.
- [x] Правки администратора пишут команду и аудит.
- [x] Ops-маршруты недоступны без корректного токена.
- [x] Сверка не содержит id жизни, игрока или seed.
- [x] Ход одинокой жизни не меняет общий мир.
- [x] Все тесты game-core и API проходят.
- [x] `/worlds` показывает общий мир отдельно от статичных карточек и личной жизни;
  шесть вселенных открывают детали в той же странице, RU/EN, без горизонтальной прокрутки
  на 390 px.
