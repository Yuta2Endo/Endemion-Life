# Аккаунты и сессии

## Модель

```
Player (игрок) ──< Session (устройство, cookie)
   │  └──< Life (жизни), GameAction
   └── Account (0..1): почта, хеш пароля, подтверждение
Account ──< AuthToken: коды подтверждения почты, ссылки восстановления
```

- Жизни принадлежат **игроку**, а не аккаунту. Гость — игрок без аккаунта. При регистрации гость сам становится владельцем аккаунта, поэтому его жизни никуда не переносятся.
- **Сессия** — одно устройство или браузер. В cookie `el_session` лежит случайный токен (32 байта, base64url), в таблице `sessions` — только его SHA-256, срок 365 дней, время последнего обращения, User-Agent и отметка отзыва.
- Cookie: `HttpOnly`, `SameSite=Lax`, `Path=/`, `Secure` при `COOKIE_SECURE=true` (по умолчанию в `NODE_ENV=production`).

### Совместимость с гостевыми сессиями Stage 01

Миграция `20261102180000_accounts_and_sessions` переносит прежнее поле `players.session_hash` в таблицу `sessions` до удаления столбца (срок — 365 дней от последнего визита). Cookie, выданные на Stage 01, продолжают работать: это проверено и на копии базы, и тестом API «гостевая сессия Stage 01 работает».

## Пароли

- scrypt (N=2¹⁵, r=8, p=1, соль 16 байт, ключ 32 байта), формат `scrypt$N$r$p$соль$ключ`. Сравнение — `timingSafeEqual`, пароль нормализуется NFKC.
- Длина 10–128 символов, пароль не может совпадать с почтой.
- Для неизвестной почты вход проверяет пароль против фиктивного хеша: по времени ответа нельзя понять, существует ли аккаунт. Ответ одинаковый: `401 INVALID_CREDENTIALS`.
- 5 неудачных попыток подряд — вход блокируется на 15 минут (`429`). Счётчик в базе, растёт атомарно: параллельный перебор упирается в тот же порог.

## Подтверждение почты

- После регистрации на почту уходит 6-значный код, действует 30 минут. В базе хранится `sha256(accountId:код)`.
- 5 попыток на код. Попытка засчитывается **до** сравнения условным `UPDATE … WHERE attempts < 5`: 20 одновременных запросов дают не больше 5 проверок (есть тест).
- Новый код (`resend-verification`) аннулирует прежние. Не чаще раза в минуту и не больше 5 в час.
- Без подтверждения аккаунтом можно пользоваться; подтверждение нужно, чтобы адрес считался принадлежащим игроку.

## Восстановление доступа

- `forgot-password` всегда отвечает `{ ok: true }`, даже для незарегистрированной почты.
- Ссылка `PUBLIC_URL/reset-password?token=…`: 32 случайных байта, в базе SHA-256, действует 1 час, одноразовая (условное `UPDATE … WHERE used_at IS NULL`). Новая ссылка аннулирует прежние. Не чаще раза в минуту и 5 в час.
- После смены пароля **все** сессии аккаунта завершаются, блокировка снимается, почта считается подтверждённой (владелец доказал доступ к ящику).
- Страница `/reset-password` отдаётся с `Referrer-Policy: no-referrer` и `noindex`: токен не уходит на сторонние сайты.

## Перенос гостевых жизней

| Ситуация | Что происходит |
| --- | --- |
| Гость регистрируется | Игрок гостя становится игроком аккаунта. Старый токен сессии отзывается, выдаётся новый |
| Гость входит в существующий аккаунт | В одной транзакции: строка игрока-гостя блокируется (`SELECT … FOR UPDATE`), его жизни и действия переходят игроку аккаунта, игрок-гость удаляется вместе с сессиями. Снимки и история привязаны к жизни и переходят вместе с ней |
| Вошедший в аккаунт входит в другой аккаунт | Ничего не переносится: переносятся только жизни игрока **без аккаунта**, чья cookie пришла в этом запросе |
| Два одновременных входа с одной гостевой cookie | Второй ждёт блокировку, гостя уже нет — перенос один раз (есть тест) |

Присвоить чужие жизни нельзя: перенос берёт только игрока из сессии самого запроса, а все запросы к жизням фильтруются по `playerId` текущей сессии. Чужая жизнь — `404` на чтение, действие, историю, сохранения и откат (есть тест).

## Ограничения частоты

| Где | Что | Лимит |
| --- | --- | --- |
| Nginx | `/api/auth/*` | 30 в минуту с адреса, burst 10 |
| API `AuthThrottle` | register, login, forgot-password — на адрес и на почту; verify-email, resend, reset — на адрес | `AUTH_RATE_LIMIT_PER_MINUTE` (10). Redis, без Redis — счётчик в памяти процесса |
| API | Попытки кода, повторная отправка, вход | См. разделы выше (в базе) |
| API `RateLimitGuard` | Все запросы | `RATE_LIMIT_PER_MINUTE` (120), только при доступном Redis |

## CSRF

Все изменяющие запросы — `POST` с JSON. Общий `RequestGuard` принимает их только с `Content-Type: application/json` и `Origin` из `CORS_ORIGINS` (иначе 415 / 403). `SameSite=Lax` дополнительно не отправляет cookie в межсайтовых POST.

## API

| Метод и путь | Тело | Ответ |
| --- | --- | --- |
| `GET /api/auth/me` | | `{ player, account }` (оба `null` без сессии) |
| `POST /api/auth/register` | `{ email, password }` | `201 { player, account, verificationSent }`; `409 EMAIL_TAKEN`, `409 ALREADY_SIGNED_IN` |
| `POST /api/auth/login` | `{ email, password }` | `{ player, account, transferredLives }`; `401 INVALID_CREDENTIALS`, `429` |
| `POST /api/auth/logout` | `{}` | `{ ok: true }`, cookie удаляется, сессия отозвана |
| `POST /api/auth/verify-email` | `{ code }` | `{ account }`; `400 INVALID_CODE` |
| `POST /api/auth/resend-verification` | `{}` | `{ verificationSent }`; `429` |
| `POST /api/auth/forgot-password` | `{ email }` | `{ ok: true }` всегда |
| `POST /api/auth/reset-password` | `{ token, password }` | `{ ok: true }`; `400 INVALID_TOKEN` |
| `GET /api/auth/sessions` | | `{ sessions: [{ id, userAgent, createdAt, lastSeenAt, current }] }` |
| `POST /api/auth/sessions/revoke` | `{ sessionId }` | `{ ok: true }`; чужая сессия — `404` |
| `POST /api/auth/sessions/revoke-others` | `{}` | `{ revoked }` |

Сайт: `/account` (вход, регистрация, подтверждение, устройства, выход), `/reset-password`, ссылка «Аккаунт» / «Войти» в шапке.

## Почта

| `MAIL_DRIVER` | Когда | Поведение |
| --- | --- | --- |
| `smtp` | Задан `SMTP_URL` | nodemailer, `MAIL_FROM` |
| `file` | Разработка без SMTP (по умолчанию вне production) | JSON-файлы в `.mail-outbox/` — из них Playwright берёт коды. В production запрещён |
| `memory` | Тесты API | Письма в массиве |
| `none` | Production без `SMTP_URL` | Письма не отправляются, `verificationSent: false` |

**Без `SMTP_URL` в рабочей среде** регистрация и вход работают, но подтвердить почту и восстановить пароль нельзя. Нужен SMTP-сервер (провайдер почты домена, Yandex 360, Mailgun, Postmark и т. п.) и записи SPF/DKIM для `endemion.online`. Отправка через настоящий SMTP **не проверялась**.

Текст писем в журналы не попадает; при ошибке отправки пишется только тема и причина.
